# 테스트 서버 배포 및 기존 U.STRA 통합 안내

## 현재 패키지의 배포 성격
이 ZIP의 `frontend/`는 React 기반 정책 협의용 UI 프로토타입입니다. 기존 U.STRA의 Java/Gradle 모듈, 인증, DB, API와 통합된 완성 애플리케이션이 아닙니다. 서버 담당자는 기존 U.STRA 소스의 작업 사본에 무조건 덮어쓰지 말고, 아래 순서로 격리 검증해야 합니다.

## 권장 순서
1. `saas-ustra-hr-master.zip` 원본 SHA-256을 인계자료 기준값과 확인하고 원본은 read-only 보관합니다.
2. 별도 작업 브랜치/사본을 만듭니다. Boot 4.1 Spike 후보 패치는 고객/AA/보안/운영 승인 및 실제 빌드 검증 전 운영 기준으로 사용하지 않습니다.
3. Node/npm 버전과 사내 npm registry 사용 가능 여부를 확인합니다.
4. `frontend/`에서 `npm ci`(lock 파일이 생성된 이후) 또는 최초 `npm install` 후 `npm run build`를 실행합니다.
5. 생성된 `frontend/dist/`를 테스트용 정적 웹서버 또는 승인된 기존 애플리케이션 정적 리소스 경로에 배포합니다.
6. Context Path, reverse proxy, CSP, 인증/SSO, CORS, 로그 정책은 서버 표준에 맞게 확인합니다.
7. 현재 화면은 API를 호출하지 않습니다. 실제 U.STRA API 연결 전에는 로그인 연동, 데이터 조회, 권한 검증이 되었다고 간주하지 않습니다.
8. 브라우저에서 GNB/LNB/MDI, 검색, PARTIAL 화면, HOLD/UNKNOWN 메뉴 알림, 정책 확인 목록을 점검합니다.

## 배포 전 필수 확인
- [ ] 원본 소스와 작업 사본 분리
- [ ] 고객/AA/보안/운영의 기술표준 승인 확인 (Boot 3.5.x 기준과 Boot 4.1 후보 혼동 금지)
- [ ] npm 패키지 사내 승인/취약점/license 점검
- [ ] 테스트 서버에서 실제 빌드 및 브라우저 확인
- [ ] 샘플 데이터만 노출되는지 확인
- [ ] 실제 DB/API가 연결되지 않았음을 테스트 사용자에게 명확히 안내
- [ ] 정책 미확정 메뉴에서 계산/저장/마감이 실행되지 않는지 확인
- [ ] 운영 서버 배포 금지: 이 패키지는 고객 검증용 1차 프로토타입임

## 서버 담당자에게 전달할 핵심
현재 ZIP은 테스트 서버에서 화면/메뉴 협의 흐름을 검토하기 위한 frontend overlay입니다. 기존 U.STRA 애플리케이션의 완전한 재빌드 소스나 운영 배포 패키지가 아닙니다. 실제 통합과 서버 배포 전에는 위 검증과 프로젝트 구조에 따른 조정이 필요합니다.
